# Degree versus sensitivity: exact n=14 constraints and symmetric exclusions

## Outcome and scope

The [FrontierMath problem](https://epoch.ai/frontiermath/open-problems/degree-sensitivity-boolean)
asks for a Boolean multilinear polynomial improving the known exponent
`log(6)/log(3)`.  The first unresolved fully sensitive parameter set examined
here is `n=14`, `degree<=5`, normalized by

```text
f(0)=0 and f(e_i)=1 for i=1,...,14.
```

No such truth table was found and no nonexistence proof was obtained.  The
result of the full search is therefore **UNKNOWN**.  This note records exact
necessary conditions that substantially shrink that case; it does not claim
that the conditions are new to the literature.  A later section,
[Symmetric subclasses and the degree-4 case](#symmetric-subclasses-and-the-degree-4-case),
certifies that no solution is invariant under several permutation groups and
that degree 4 cannot improve the exponent.

## Exact layer bounds

Let `B_t` be the number of inputs of Hamming weight `t` on which `f=1`, and
put `q(t)=B_t/binom(14,t)`.  Symmetrizing a degree-five multilinear polynomial
shows that `q` is a univariate polynomial of degree at most five, with
`q(0)=0`, `q(1)=1`, and `0<=q(t)<=1` on all integer layers.

Interpolating `q(2)` at nodes `(0,1,5,9,13,14)` gives coefficients

```text
(-22/65, 231/208, 77/240, -11/80, 21/208, -11/195).
```

Choosing the endpoints of the unknown `[0,1]` values according to coefficient
sign gives `q(2)>=11/12`.  Hence

```text
B_2 >= 84,
```

so at most seven of the 91 pair inputs can be zero.  Two further exact
interpolations, retaining `q(2)`, give

```text
300 B_3 - 1925 B_2 >= -108801,
 21 B_3 -  180 B_2 <=  -11375.
```

There is a stronger integrality consequence.  Interpolation from layers
`0,...,5` expresses every later `B_t` as an integer linear form in
`B_0,...,B_5`.  Exhausting the resulting two-dimensional integer intervals
leaves exactly 247 possible `(B_2,B_3,B_4,B_5)` profiles:

| `B_2` | possible `B_3` interval | profiles |
|---:|---:|---:|
| 84 | 178 | 1 |
| 85 | 184--186 | 5 |
| 86 | 190--195 | 11 |
| 87 | 196--204 | 24 |
| 88 | 203--212 | 31 |
| 89 | 210--221 | 42 |
| 90 | 215--229 | 58 |
| 91 | 222--238 | 75 |

In the most constrained case the complete layer vector is forced to

```text
(B_0,...,B_14) =
(0,14,84,178,123,28,525,1716,2478,1974,878,186,7,0,1).
```

Run the dependency-free exact certificate and enumeration with:

```bash
python3 problems/degree-vs-sensitivity/degree_sensitivity_pair_bound.py
```

Every displayed rational identity and cleared integer inequality is asserted
inside the script.

## Truth-table search

`degree_sensitivity_cpsat.py` represents all 16,384 Boolean truth values and
computes the full Möbius transform through 114,688 shared subtraction
equations.  All coefficients above degree five are fixed to zero.  It also
adds the 247-profile table and a safe symmetry split according to the maximum
degree of the graph of zero-valued pairs.

A six-variable degree-three regression instance is found and independently
verified in about 0.02 seconds.  For the target case, unsplit HiGHS and CP-SAT
runs and the two extreme graph branches (`0` and `7`) all ended at their time
limits with status `UNKNOWN`; no certificate file was emitted.  In particular,
the 120-second strengthened runs did not decide either extreme branch, and the
six intermediate branches were not exhausted.

One reproduction command, after installing OR-Tools in a disposable virtual
environment, is:

```bash
python -m venv /tmp/degree-sat-venv
/tmp/degree-sat-venv/bin/pip install ortools
/tmp/degree-sat-venv/bin/python \
  problems/degree-vs-sensitivity/degree_sensitivity_cpsat.py \
  --n 14 --degree 5 --max-zero-degree 7 --time-limit 120 --workers 4
```

`UNKNOWN` is only a timeout status.  It is neither evidence that a construction
exists nor evidence that none exists.

## Symmetric subclasses and the degree-4 case

### Statements

Call `f:{0,1}^14 -> {0,1}` a *normalized solution* if its multilinear degree
is at most 5, `f(0)=0`, and `f(e_i)=1` for every `i`.  For a permutation group
`G` of the 14 coordinates, `f` is *`G`-invariant* if permuting the input by
any element of `G` never changes `f`.  A `G`-invariant normalized solution
would already improve the exponent, so each class below was a legitimate
place to look.  The following statements are certified in exact integer
arithmetic.  Relabelling coordinates preserves degree and the normalization,
so each statement applies to every conjugate of the group named.

1. **Cycle type `7^2`.**  No normalized solution is invariant under the
   cyclic group `C7(7^2)` generated by `(0 1 ... 6)(7 8 ... 13)`.  Hence no
   normalized solution is invariant under *any* permutation of cycle type
   `7^2`, or under any 14-cycle (its square has cycle type `7^2`).  This
   subsumes every group considered in this section that contains such an
   element: `C14`, `D7` (regular and diagonal), `C7 x C7`, `Z_2^3:Z_7`,
   `PSL(2,7)`, `PGL(2,7)`, `AGL(3,2)`, `A_7` acting diagonally on two
   7-blocks, `S_7` with the sign twist, `S_7 wr S_2`, `S_2 wr S_7`,
   `PSL(2,13)`, and `PGL(2,13)`.
2. **13-cycle Frobenius groups.**  With a 13-cycle `x -> x+1` on `F_13` and
   the 14th point fixed, no normalized solution is invariant under
   `C13:C3` or `D13 = C13:C2`.  This rules out `C13:C4`, `C13:C6`, and
   `AGL(1,13)` too, which contain one of the two.  The cyclic group `C13`
   itself is **not** decided.
3. **Block-symmetric functions.**  No normalized solution is symmetric inside
   each of at most four blocks of variables, that is, no normalized solution
   is invariant under any Young subgroup `S_lambda` with `lambda` a partition
   of 14 into at most four parts.  Of these 47 partitions, 18 are excluded by
   counting alone and 29 by Farkas trees.  The 24 partitions with at most
   three parts are checked in CI from committed certificates.  The 21
   four-part certificates (89 MB together) are local only.
4. **Degree 4.**  No Boolean function on 10 variables of degree at most 4
   satisfies `f(0)=0` and `f(e_i)=1` for `i=1,...,10`.  Restricting a function
   to ten coordinates that are sensitive at one input, translating that input
   to `0`, and negating if necessary shows the following.  **Every Boolean
   function of degree at most 4 has sensitivity at most 9**, so degree 4 can
   never beat the exponent.  Beating it would need
   `s >= 10 > 4^(log 6/log 3) = 9.59`.  The value 9 is attained by
   `NAE_3(NAE_3, NAE_3, NAE_3)` with `NAE_3 = x1+x2+x3-x1x2-x1x3-x2x3`
   (degree 2, fully sensitive at `0`).  This consequence may well be known in
   the literature; it is not claimed as new.

Nothing here decides the full `n=14`, `degree<=5` case, which stays
**UNKNOWN**.

### Method

The variables are the `G`-orbits `O` of subsets of the coordinates (an input
is identified with its support), with `y_O` the common value of `f` on `O`.
All constraints are exact linear equalities with integer coefficients.

- **Cube identities.**  For a multilinear polynomial of degree at most `d`,
  the mixed difference in any `d+1` directions vanishes.  For every set `T`
  with `|T|>d` and every `(d+1)`-subset `S` of `T`,
  `sum over U subset of S of (-1)^|U| f(T \ U) = 0`.  The search uses one
  identity per orbit representative `T`, with `S` the `d+1` largest
  coordinates of `T`.  These identities equal `sum_{S <= R <= T} c_R`
  (with `c_R` the Möbius coefficients), so induction on `|T|` shows that
  together they are equivalent to `deg f <= d` for `G`-invariant `f`.  The
  encoding is therefore exact, not a relaxation.
- **Layer identities.**  `sum_{O in layer t} |O| y_O = B_t`, where
  `(B_0,...,B_14)` is one of the 247 integral layer vectors from the previous
  section.

*Counting.*  For a `G`-invariant `f`, every `B_t` is a sum of sizes of
`G`-orbits of `t`-subsets.  If no layer vector passes this subset-sum test on
all 15 layers, the class is empty.

*Farkas trees.*  For each surviving layer vector, a depth-first branch and
bound fixes orbit variables to 0 or 1.  Every leaf stores an integer
multiplier vector `lambda` over the identities with
`max (lambda^T A) y < lambda^T b`, where the maximum is over the leaf's box:
fixed variables at their values, free variables in `[0,1]`.  Any Boolean point
of the box satisfying `Ay=b` would give `lambda^T A y = lambda^T b`, so the
leaf contains no solution.  The root box already fixes `f(0)=0` and
`f(e_i)=1`.

The search (`degree_sensitivity_symmetric_search.py`, HiGHS through
`highspy`) uses floating-point duals only to *propose* multipliers.  The
checker (`degree_sensitivity_symmetric.py`, Python standard library only)
does the following:

- recomputes every identity from its key (`[top, directions]` or `[layer]`);
- rejects malformed keys;
- requires both children at every branch;
- requires the certificate to cover every layer vector that survives counting
  for that group;
- does all leaf arithmetic with Python integers.

A tampering test (scaling one multiplier, dropping entries, reusing a
subtree, altering a key, a layer vector, or the generators) was rejected in
every case.  The groups are built from explicit generators in the checker:
Möbius maps on `P^1(F_13)`, affine maps on `F_13`, `GL(3,2)` on Fano points
and lines, `AGL(3,2)` on the 14 affine planes of `AG(3,2)`, and cycles.

### Reproduction

The CI check uses the standard library only.  It runs the counting
exclusions, checks the 16 committed certificates in
`symmetric_certificates/` (1.9 MB), and asserts the three-block Young claim.
It takes about 3 s:

```bash
python3 problems/degree-vs-sensitivity/degree_sensitivity_symmetric.py
```

The large certificates are not committed.  Regenerate and check them as
follows; the search needs `numpy` and `highspy`, the checker needs only
Python:

```bash
cd problems/degree-vs-sensitivity
python degree_sensitivity_symmetric_search.py --group 'C7(7^2)' --out /tmp/c7_7x2.json
python degree_sensitivity_symmetric_search.py --group D13 --out /tmp/d13.json
python degree_sensitivity_symmetric_search.py --group D7-diagonal --out /tmp/d7diag.json
python degree_sensitivity_symmetric_search.py --group trivial --n 10 --degree 4 \
  --out /tmp/n10_d4.json
python3 degree_sensitivity_symmetric.py --skip-counting /tmp/c7_7x2.json \
  /tmp/d13.json /tmp/d7diag.json /tmp/n10_d4.json

# Four-block Young subgroups; --young-blocks 4 also checks the committed
# certificates and asserts that all 47 partitions with <= 4 parts are covered.
mkdir -p /tmp/young4
for p in 9,3,1,1 8,4,1,1 9,2,2,1 7,5,1,1 6,6,1,1 8,3,2,1 7,4,2,1 8,2,2,2 \
         6,5,2,1 7,3,3,1 6,4,3,1 5,5,3,1 7,3,2,2 5,4,4,1 6,4,2,2 5,5,2,2 \
         6,3,3,2 5,4,3,2 4,4,4,2 5,3,3,3 4,4,3,3; do
  python degree_sensitivity_symmetric_search.py --group "young:$p" \
    --out "/tmp/young4/young_$(echo "$p" | tr , _).json"
done
python3 degree_sensitivity_symmetric.py --young-blocks 4 /tmp/young4/*.json
```

With HiGHS 1.15.1 on macOS, regeneration is deterministic: two runs for
`Z_2^3:Z_7` produced byte-identical files.  Other platforms or versions may
produce different but equally checkable trees, so the SHA256 values above
only identify the files checked here.

### Cross-checks (not certificates)

- The committed `degree_sensitivity_cpsat.py --n 10 --degree 4 --workers 1`
  uses a different encoding (the full Möbius circuit).  It ended **UNKNOWN**
  after 1800 s.  That is a timeout, not evidence either way.
- During exploration, separate orbit-variable CNF (kissat) and CP-SAT
  encodings in scratch code, not committed, agreed on every exclusion they
  finished.  These were the counting-excluded named groups, the two-block
  Young subgroups, `C14`, both `D7` actions, `C7 x C7`, `Z_2^3:Z_7`,
  `AGL(1,13)`, `C13:C3`, `C13:C4`, `C13:C6`, `D13`, and `n=10`, `d=4`.

### Not decided

- `C13` (one 13-cycle and a fixed point; 1264 orbits, one layer vector) and
  `C11` (one 11-cycle and three fixed points; 1504 orbits, three layer
  vectors) are **not decided**.  Their Farkas-tree searches were stopped after
  about 50 minutes each, at 1605 and 806 nodes, without finding an integral
  point.  Earlier, CP-SAT with 3 workers ended UNKNOWN after 1800 s on both,
  and also on `C7(7^2)`, which the Farkas tree later closed.
- Not attempted: a single 7-cycle with 7 fixed points (2560 orbits, all 247
  layer vectors survive counting), elements of order 2, 3, or 5, and Young
  subgroups with five or more blocks.
- Degree 6 with `n >= 19` was not attempted.  An exploratory floating-point
  LP, not a certificate, finds the univariate symmetrization relaxation
  feasible up to `n=21`, so no layer-average obstruction is available there.
