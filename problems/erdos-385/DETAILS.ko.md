# 에르되시 #385: 증명과 유한 인증서 상세

## 1. 정의와 정확한 유한 명제

합성수 $m$의 최소 소인수를 $p(m)$이라 하고

\[
F(n)=\max_{\substack{m<n\\m\text{ 합성수}}}(m+p(m))
\]

으로 둡니다. 여기서 증명하는 컴퓨터 보조 정리는 다음과 같습니다.

\[
\boxed{267681\le n\le10^9\quad\Longrightarrow\quad F(n)>n.}
\tag{E385-1}
\]

Lean으로 증명한 $n\ge5$에서의 하한 $F(n)\ge n$과 결합하면, 인증서는
해당 범위의 모든 등호도 분류합니다.

\[
\#\{n:6\le n\le10^9,\ F(n)=n\}=100,
\]

가장 큰 등호 사례는 $n=267680$입니다. 전체 목록은 사람이 관리하는 표가
아니라 인증서 데이터로 [`billion_result.json`](billion_result.json)에
저장되며, 검증기를 실행할 때마다 확인됩니다.

1979년 원문은 $F(n)\le n$인 지표가 무한히 많은지를 묻고, 이어서 소수에
관한 그럴듯한 추측들을 가정하면 그런 지표는 유한 개뿐일 것이라고
설명합니다. 현재 문제 페이지는 반대 방향의 동치인 궁극적 질문
$F(n)>n$과 $F(n)-n$의 발산을 묻습니다. 유한 정리 (E385-1)은 현재 형식을
다루지만 어느 질문도 결정하지 않습니다.

## 2. 무한한 초등적 부분족

먼저 $n\ge5$가 홀수라고 합시다. 그러면 $m=n-1\ge4$는 짝수
합성수이고 $p(m)=2$입니다. 따라서

\[
F(n)\ge m+p(m)=(n-1)+2=n+1>n.
\tag{E385-2}
\]

$n\ge5$가 짝수이면 실제로 $n\ge6$입니다. 이때 $m=n-2\ge4$는
짝수 합성수이므로

\[
F(n)\ge(n-2)+2=n.
\tag{E385-3}
\]

두 논증은 `AgenticConjectures.Erdos385.odd_index_lt_F`와
`AgenticConjectures.Erdos385.index_le_F`로 형식화했습니다. 따라서 계산이
기록하는 모든 예외값은 엄격한 실패가 아니라 등호 사례입니다.

## 3. 덮임 구간

합성수 $m$이 $F(n)>n$을 보이는 정확한 범위는

\[
m<n<m+p(m),
\]

즉 정수 구간

\[
n\in[m+1,m+p(m)-1]
\tag{E385-4}
\]

입니다. $n$을 증가시키며 탐색할 때 가장 먼 덮임 끝점을

\[
R(n)=\max_{\substack{m<n\\m\text{ 합성수}}}(m+p(m)-1)
\]

로 두면

\[
F(n)-n=R(n)+1-n
\tag{E385-5}
\]

입니다. 조밀 구현은 상한까지 모든 정수의 최소 소인수를 만든 뒤 이
항등식을 직접 계산합니다.

두 번째 저메모리 환원도 있습니다. 홀수 $n\ge5$에서는 (E385-2)가 이미
엄격한 부등식을 줍니다. 짝수 $n\ge6$에서 짝수 합성수 $m<n$은 모두
$p(m)=2$이므로 $m+p(m)\le n$입니다. 따라서 엄격한 개선은 홀수
합성수에서만 올 수 있습니다. 그러므로 홀수만 분할 체로 거르고 기록적인
덮임 끝점만 유지하면 충분하며, (E385-3)이 등호 기준선을 제공합니다.

## 4. 두 독립 완전탐색 구현

검증기는 다음의 독립 알고리즘을 사용합니다.

1. `ep430_experiment.cpp`는 조밀한 오일러 체를 사용합니다.
   $m\le10^9$인 모든 `spf[m]`을 저장하고 각 정수를 한 번 방문하여 끝점
   $m+p(m)-1$을 갱신합니다.
2. `ep430_segmented.cpp`는 먼저 $\sqrt{10^9}$까지만 소수를 구하고,
   16,000,000 크기 블록에서 홀수의 최소 소인수를 표시합니다. 조밀
   프로그램의 전 정수 점화식 대신 위의 홀짝 환원을 사용합니다.

Python 래퍼는 마지막 예외값만 일치하는 것으로는 통과시키지 않습니다.
100개 등호 사례의 전체 목록과

\[
\max\{n\le10^9:F(n)-n\le t\}
\]

을 $t\in\{0,1,2,3,5,10,20,50,100,200,500,1000\}$ 각각에 대해 비교합니다.
그 뒤 이 객체들을 커밋된 JSON 인증서와 대조합니다. 구현이 불일치하거나
인증서가 바뀌면 명령은 실패합니다.

## 6. 충실성과 범위

공식 정의와 FormalConjectures 정의는 모두 합성수 $m<n$에 대해 같은
값을 최대화합니다. 로컬 Lean 모듈은 합성수를 $1<m$이면서 $m$이
소수가 아닌 경우로 명시하고 유한 `Finset.sup`을 사용합니다. 후보 집합이
비었을 때의 값만 의미론적으로 다르지만, 모든 주장은 $m=4$를 사용할 수
있는 $n\ge5$에서 시작합니다. 프로그램의 `uint32_t` 지표는
$n\le10^9$ 전체에서 정확하고, 끝점 산술은 `uint64_t`로 올려 계산합니다.

(E385-1)도 홀수 지표 정리도 임의로 큰 짝수 지표를 통제하지 않습니다.
특히 충분히 큰 모든 지표에서의 엄격한 부등식, $F(n)-n\to\infty$, 또는
추측되는 $(1-o(1))\sqrt n$ 하한을 증명하지 않습니다. 공식 페이지는
여전히 문제를 미해결로 표시하며, 외부 검토 전에는 새로움을 주장하지
않습니다.
