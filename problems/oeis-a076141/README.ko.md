# OEIS A076141의 계산적 진전

2026-08-11에 `n < 2^40` 범위를 확인했고, 2026-10-24에 이를 `n < 2^100`
범위로 확장했습니다. 둘 다 엄밀한 유한 범위 검증이며, 추측 전체의 증명은
아닙니다. 또한 Lean 4로 모든 `n`에 대해 더 약한 상계 `a(n) <= 2`를
증명했습니다.

출현 기하 논증 전체는 [문제별 상세 설명](DETAILS.ko.md)에 있습니다. 그
문서의 1–7절은 `2^40` 탐색을, 8절은 이번 확장을 다룹니다.

## 문제와 결과

OEIS A076141은 `n`의 2진 단어가 `n^2`의 2진 단어 안에 나타나는 횟수를
셉니다(겹치는 출현도 셉니다). 이 수열의 열린 질문은 그 횟수가 항상 1
이하인가 하는 것입니다. OEIS 페이지에는 `n <= 10^6`까지의 검증만 기록되어
있습니다.

정확한 완전탐색 프로그램 `a076141_pair_geometry.cpp`는 다음 범위에서 반례를
찾지 못했습니다.

```text
0 < n < 2^40 = 1,099,511,627,776.
```

이는 기록된 검증 구간을 약 110만 배 넓힌 것입니다.

2026-10 확장(아래 "`n < 2^100`으로의 확장" 절)에서는 서로 독립인 두 개의
단일 출현 열거기를 사용했고, 다음 범위에서 반례를 찾지 못했습니다.

```text
0 < n < 2^64  = 18,446,744,073,709,551,616              (모든 비트 위치)
0 < n < 2^100 = 1,267,650,600,228,229,401,496,703,205,376 (축소된 위치)
```

축소된 위치만 조사해도 되는 근거는 Lean 4로 증명한 쌍 보조정리입니다.
`2^64` 범위의 결과는 이 보조정리에 의존하지 않습니다. 같은 보조정리로부터
계산 없이 모든 `n`에 대해 무조건적인 상계 `a(n) <= 2`도 얻습니다(Lean 정리
`a_le_two`).

OEIS 출처: <https://oeis.org/A076141>

## 프로그램이 사용하는 완전 환원

`n`의 비트 길이를 `L`이라 합시다. 모든 `n`을 직접 조사하기에는 범위가 너무
크므로, 프로그램은 두 출현이 이룰 수 있는 모든 기하를 열거합니다.

* 최하위 끝의 출현은 `n=1`을 강제합니다.
* 최상위 끝의 출현은 `n`이 2의 거듭제곱임을 강제하며, 그 출현은
  유일합니다.
* 그 밖의 경우, `2L`비트 또는 `(2L-1)`비트 단어 `n^2` 안의 길이 `L`인 두
  출현은 반드시 겹칩니다. 두 시작 위치의 차가 `d`이면, `n`의 2진 단어는
  길이 `r=L-d`인 겹침 위에서 주기 `d`를 가집니다.

프로그램은 각 `L`, 겹침, 제곱의 길이, 비어 있지 않은 접두부/접미부 기하마다
주기적인 겹침 단어 `q`를 열거합니다. 남은 미지의 접두부 `A`는 제곱의 범위가
허용하는 정확한 구간으로 제한됩니다. 그러면 출현 방정식은 다음과 같이
환원됩니다.

```text
n^2 - C*n = A*2^E - q*2^(d+s) + B,
C = 2^s*(2^d+1),
```

여기서 `B`는 `q^2`의 하위 `s`비트로 정해집니다. 따라서 판별식이
완전제곱일 때만 후보가 생깁니다. 그런 근은 모두 복원하며, 두 출현은
`n^2`와 직접 비교해 확인합니다.

모든 산술은 정확한 부호 없는 128비트 산술입니다. `L<=40`이면 모든 제곱이
`2^80`보다 작으므로 지원 범위 안에 충분히 들어옵니다.

`L=40`까지의 실행에서 조사한 개수는 다음과 같습니다.

```text
q candidates:          181,402,314
quadratic candidates:   99,006,717
counterexamples:                 0
```

이 디렉터리에서의 재현 방법은 다음과 같습니다.

```bash
g++ -O3 -std=c++20 -o a076141_pair_geometry \
  a076141_pair_geometry.cpp
./a076141_pair_geometry 40
```


## `n < 2^100`으로의 확장 (2026-10)

### 명제

`0 < n < 2^100`인 모든 `n`에 대해, `n`의 2진 단어는 `n^2`의 2진 단어에
많아야 한 번 나타납니다. 즉 `a(n) <= 1`입니다. (상류 정의에서는
`a(0) = 1`입니다.)

두 범위는 서로 다른 사실에 근거합니다.

- `0 < n < 2^64`는 기초적인 사실과 모든 비트 위치에서의 완전 열거만
  사용합니다.
- `2^64 <= n < 2^100`은 여기에 더해
  [`AgenticConjectures/OeisA076141.lean`](../../AgenticConjectures/OeisA076141.lean)에서
  증명한 쌍 보조정리를 사용합니다.

이와 별도로 Lean 모듈은 모든 `n`에 대해 더 약한 상계 `a(n) <= 2`를 계산
없이 증명합니다(`a_le_two`). 홀수 `k >= 3`의 세 출현은 아래 4번 항목의 쌍
기하에 어긋나고, `2m`의 출현은 `m`의 출현으로 옮겨 가기 때문입니다
([DETAILS.ko.md 8.4절](DETAILS.ko.md)).

### 방법

증명은 [DETAILS.ko.md 8절](DETAILS.ko.md)에 있습니다.

1. 반례가 있으면 그보다 크지 않은 홀수 반례 `k >= 3`이 있습니다(Lean).
   비트 길이가 `L`인 홀수 `k >= 3`의 모든 출현은 `3 <= t <= L-1`인 비트
   위치 `t`에서 시작합니다(Lean).
2. 고정된 위치 `t`에서 홀수 `n`의 출현은 두 가지 방법으로 결정됩니다.
   하위 부분 `B = n^2 mod 2^t`는 2진 제곱근을 통해 출현을 결정합니다. 이것이
   하단 방법이며 후보는 `2^(t-3)`개입니다. 상위 부분
   `A = floor(n^2 / 2^(t+L))`은 정수 제곱근을 통해 출현을 결정합니다. 이것이
   상단 방법이며 후보는 약 `3*2^(L-t-2)`개입니다. 모든 후보는 정확한
   제곱과 비교해 확인합니다. 찾아낸 `n`마다 모든 출현을 세며, 그 수가 2
   이상이면 반례로 보고합니다.
3. 전체 계획은 모든 위치 `3 <= t <= L-1`을 조사하며, `L`마다
   `O(2^(L/2))`의 비용이 듭니다. `L <= 64`에 사용했습니다.
4. 축소 계획은 Lean 정리 `pair_geometry`에 근거합니다. 홀수 `n >= 3`의
   두 출현 `s < t`는 `3 <= s`, `2s <= t`, `L+s <= 2t`, `t < L`을
   만족합니다. 따라서 둘 중 하나는 `[3, sigma]` 또는 `[tau, L-1]`에
   있습니다. 여기서 `sigma = floor(L/3)+1`,
   `tau = max(2*sigma+2, ceil((L+sigma+1)/2))`입니다. 이 위치만 조사하면
   `L`마다 `O(2^(L/3))`의 비용이 듭니다. `L <= 100`에 사용했습니다.
5. 독립적으로 작성한 두 프로그램이 두 계획을 모두 구현합니다.
   - P(`a076141_occ_closed.cpp`)는 2진 역제곱근(하단)과 정수 제곱근(상단)을
     사용합니다.
   - Q(`a076141_occ_hensel.cpp`)는 비트 단위 Hensel 들어 올리기(하단)와
     `n^2 - 2^t n`에 대한 정확한 갤로핑 탐색(상단)을 사용하며, 제곱근을 쓰지
     않습니다.

   두 프로그램은 후보 수를 포함한 `L`별 요약 줄과 `OCC L t n count` 목록을
   똑같이 출력해야 합니다. `a076141_bruteforce_odd.cpp`는 모든 홀수 `n`의
   모든 창을 직접 조사합니다.
6. `a076141_crosscheck.py --smoke`는 세 프로그램을 컴파일해 서로
   비교합니다. `a076141_crosscheck.py --logs`는 커밋된 로그를 다시
   검사합니다. 검사 항목은 다음과 같습니다.
   - 종료 상태 0과 `counterexamples=0`;
   - 각 출현 목록에 기록된 SHA-256;
   - P = Q;
   - `L`에 빠진 구간이 없음;
   - 둘 다 있는 범위에서, 축소 모드 목록이 전체 모드 목록을 축소된 위치로
     제한한 것과 같음;
   - 전수 조사 목록이 그 범위에서 전체 모드 목록과 같음.

### Lean 선언

모든 선언은 이름공간 `AgenticConjectures.OeisA076141`에 있습니다.

| 선언 | 내용 |
|---|---|
| `list_count_infix`, `binary_pattern_nat`, `a` | 상류 정의를 항 그대로 옮긴 것 |
| `statement` | 상류 추측 `∀ n, a n ≤ 1` (열린 문제이며 여기서 증명하지 않음) |
| `Occ n L s` | `n ^ 2 / 2 ^ s % 2 ^ L = n` (비트 위치 `s`의 출현) |
| `a_eq_countP` | `n ≠ 0`이면 `a n`은 `Occ`가 성립하는 창 위치의 수 |
| `a_zero` | `a 0 = 1` |
| `occ_lt`, `three_le_of_occ` | 홀수 `n ≥ 3`의 출현은 `3 ≤ s < L`에서 시작 |
| `occ_of_occ_two_mul`, `occ_descent`, `exists_odd_of_two_occ` | 출현이 `2n`에서 `n`으로, 따라서 홀수 부분으로 단사적으로 옮겨 감 |
| `not_occ_pair_of_close` | `2d+s+1 ≤ L`이면 `s`, `s+d`의 쌍은 없음 |
| `not_occ_pair_of_far` | `d < s`, `s+d < L`, `2^(L-1) ≤ n`이면 `s`, `s+d`의 쌍은 없음 |
| `pair_geometry`, `pair_covered` | `3 ≤ s`, `2s ≤ t`, `L+s ≤ 2t`, `t < L`; 축소된 위치가 모든 쌍을 포괄 |
| `exists_two_occ_of_two_le_a`, `reduction` | `2 ≤ a n`이면 그런 쌍을 가진 홀수 `k ≤ n`, `k ≥ 3`이 존재 |
| `a_le_two` | 모든 `n`에 대해 `a n ≤ 2` (무조건적이며 탐색을 쓰지 않음) |
| `SearchedPos`, `a_le_one_of_search` | 모든 `L ≤ N`에 대해 탐색이 확인하는 가정이 성립하면 `n < 2^N`에서 `a n ≤ 1` |

### 명제의 충실성

Lean 모듈은 `list_count_infix`, `binary_pattern_nat`, `a`를
[`upstream/76141_34382c19.lean`](upstream/76141_34382c19.lean)에서 항
그대로 옮겼습니다. `statement`는 `oeis_a076141_conjecture`의 명제입니다.

- **첨자 기준.** 상류 정의는 뒤집은 `Nat.digits 2` 목록에서 최상위 끝으로부터
  오프셋 `i`인 창을 비교합니다. `Occ`는 최하위 끝으로부터 비트 위치 `s`를
  셉니다. `a_eq_countP`는 `s = M - L - i`임을 증명합니다. 여기서 `M`과
  `L`은 각각 `n^2`과 `n`의 2진 길이입니다.
- **자연수 뺄셈.** 잘린 뺄셈은 `i ≤ M - L`인 `M - L - i`에만 나타납니다.
- **경계값.** 상류 정의에서 `n = 0`은 특별한 경우로, 패턴이 `[0]`이므로
  `a 0 = 1`입니다(`a_zero`). 이 값은 탐색에서 제외되며 반례가 아닙니다.
- **상계 `a_le_two`.** 상류 정의의 `a`에 대해 직접 진술했으므로,
  `∀ n, a n ≤ 2`는 `statement`를 약화한 명제(`1` 대신 `2`)의 완전한 Lean
  증명입니다.
- **정리가 남겨 두는 부분.** 유한 명제 "모든 `n < 2^100`에서 `a n ≤ 1`"은
  `a_le_one_of_search`(`N = 100`)에 의해 프로그램이 확인하는 `L`별 가정으로
  환원됩니다. 그 가정 자체는 Lean으로 증명하지 않았고, 하단·상단 방법의
  완전성도 형식화하지 않았습니다.

있습니다.

### 주장하지 않는 것

- 모든 `n`에 대한 추측의 증명은 주장하지 않습니다. 무조건적인 결과는 더 약한
  상계 `a(n) <= 2`뿐입니다.
- 열거기의 완전성, 프로그램, 컴파일러는 형식적으로 검증하지 않았습니다. 이
  위험은 줄 단위로 일치하는 두 독립 구현과 `L <= 34`에서의 전수 조사 일치로
  줄였습니다.
- `2^64 <= n < 2^100` 범위는 Lean 쌍 보조정리에 의존하지만, `n < 2^64`
  범위는 의존하지 않습니다.
- 새로움이나 우선권은 주장하지 않습니다.

## 한계

이것은 유한 명제 `n<2^40`(쌍 기하)과 `n<2^100`(단일 출현; `n<2^64`는 쌍
보조정리 없이), 그리고 모든 `n`에 대한 더 약한 상계 `a(n)<=2`만
증명합니다. 임의로 큰 `n`에 대한 OEIS 질문을 해결하지는
않으며, 외부 검토 전에는 새로움이나 우선권을 주장하지 않습니다.
