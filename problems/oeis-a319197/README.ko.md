# OEIS A319197 — `I(n,1)=1` 정규화 반례

## 결과

[OEIS A319197](https://oeis.org/A319197)에 공개된 항들은 Formula 절의
다음 명시적 주장을 반박한다.

> “모든 m >= 0에 공통인 1보다 큰 인자가 더 없는 이유는 I(n, 1) = 1이기 때문이다.”

원문은

\[
I(n;m)=\frac{F(2^{n-2}\,3m)}
 {2^n\prod_{j=3}^{n}a(j)}
\]

로 정의하고 다음 항들을 제시한다.

\[
(a(3),a(4),a(5),a(6),a(7))
=(1,9,161,51841,6989569).
\]

\(n=7,m=1\)에서 정확한 정수 계산은

\[
\prod_{j=3}^{7}a(j)=525039711220521,
\]

\[
2^7\prod_{j=3}^{7}a(j)=67205083036226688,
\qquad
F(96)=51680708854858323072,
\]

및

\[
F(96)=769\left(2^7\prod_{j=3}^{7}a(j)\right)
\]

를 준다. 따라서

\[
\boxed{I(7;1)=769\ne1}.
\]

이는 보조 주장 `I(n,1)=1`의 완전한 반례다. 그러나 `n >= 3`, `m >= 0`인
모든 경우에 `I(n,m)`이 음이 아닌 정수라는 별도의 중심 추측에 대한 반례는
**아니다**. `769` 자체가 양의 정수이므로 더 넓은 추측은 여기서 열린 상태로
남는다.

## 기계 검증

[Lean 모듈](../../AgenticConjectures/OeisA319197.lean)은 정확한
`n=7,m=1` 경우만 형식화한다. 커널이 확인하는 `norm_num`으로
`I(7;1)=769`와 값이 `1`이라는 주장의 부정을 모두 증명하며 `sorry`나
`native_decide`를 사용하지 않는다.

독립적인 [Python 인증서](a319197_certificate.py)는 서로 다른 두 Fibonacci
알고리즘(선형 반복과 fast doubling)을 사용해 원문의 분모와 `F(96)`을
검사하고, 나머지가 0이며 몫이 정확히 769임을 확인한다. 이 스크립트는 유한
전사 감사이고 Lean 정리가 형식적 반박이다.

저장소 루트에서 다음 명령으로 두 검사를 재현할 수 있다.

```bash
lake env lean AgenticConjectures/OeisA319197.lean
(cd problems/oeis-a319197 && python3 a319197_certificate.py)
```

2026-08-12 저장소의 CI 동등 환경에서 관측한 실행 시간은 다음과 같다.

- Lean 모듈 직접 검사: 21.57초;
- Python 인증서: 0.06초.

## 형식화 대응

- OEIS 오프셋은 3이다. 형식 반례는 정확히 `a(3)`부터 `a(7)`까지만
  사용하며 그 범위 밖에 인위적 값을 지정하지 않는다.
- `Nat.fib`의 초기값은 `F(0)=0, F(1)=1`로 OEIS A000045와 같다.
- 원문의 인덱스는 모호함 없이 `2^(7-2)*3*1 = 96`이 된다. 이 리터럴에서
  자연수 뺄셈 언더플로는 없다.
- Lean 자연수 나눗셈의 내림은 반증에 영향이 없다. Lean 정리는 내림 몫이
  769임을 증명하고(정확히 `I = 1`이면 내림 몫도 1이어야 한다), 분모가
  `F(96)`을 나머지 0으로 정확히 나눈다는 것은 Python 인증서가 독립적으로
  확인한다.
- 이 항목에 대한 상류 Lean 스냅샷은 없다.
