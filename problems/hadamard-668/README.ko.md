# Hadamard matrix of order 668

확인 기준일: 2026-08-11.

## 문제

원소가 `+1` 또는 `-1`인 `668 x 668` 행렬 `H` 중

```text
H H^T = 668 I
```

를 만족하는 행렬이 존재하는지를 묻는다.

## 현재 상태와 알려진 부분결과

Hadamard 추측은 4의 모든 배수 차수에서 이런 행렬의 존재를 예측한다.
2023년 동료평가 논문과 2026년 상태 보고서는 모두 668을 가장 작은 미해결
차수로 기록한다.

2026년 상태 보고서는 길이 333 Legendre pair를 찾는 충분조건 경로에서
다음을 보고한다.

- 9-compression의 PSD-compatible configuration 12,017,243개를 완전
  열거했다.
- 37-compression 휴리스틱에서 얻은 최선의 `L1` PSD 오차는 236이었다.

여기에는 668차 행렬의 존재 또는 비존재를 판정하는 새 결과가 없다.

이 저장소는 한 구조적 부분 부류, 즉 multiplier 부분군에 대해 불변인 길이
333 Legendre pair에 대한 완전 탐색 계산을 추가한다. 내용은
[길이 333의 multiplier-불변 Legendre pair](#길이-333의-multiplier-불변-legendre-pair)
절에 정리했다. 이 계산은 80개의 multiplier 부류 중 72개를 배제하지만 668차
문제 자체에 대해서는 아무것도 판정하지 않는다.

## 논리적 범위에 대한 주의

길이 333인 Legendre pair가 존재하면 668차 Hadamard matrix를 구성할 수
있다. 그러나 임의의 668차 Hadamard matrix가 반드시 이 형태인 것은
아니다. 따라서 상태 보고서 초록의 “equivalently”를 전체 존재 문제에
대한 논리적 동치로 사용해서는 안 된다.

Legendre-pair, Goethals--Seidel, Williamson 등의 각 구조적 부분공간은
PSD 필터, meet-in-the-middle, SAT 또는 SMT로 탐색할 수 있다. 한 구성
부류에서의 UNSAT는 전체 Hadamard 문제의 비존재 증명이 아니다.

## 길이 333의 multiplier-불변 Legendre pair

2026-10-24에 계산했다. 코드, 데이터, 로그는 [`legendre/`](legendre/)에 있다.

### 정확한 명제

길이 333의 Legendre pair는 모든 `s != 0`에 대해
`PAF_A(s) + PAF_B(s) = -2`를 만족하는 사상 `A, B : Z/333 -> {+1, -1}`의
쌍이다. 여기서 `PAF_A(s) = sum_x A(x) A(x+s)`이다. 이런 쌍은 항상
`sum(A)^2 + sum(B)^2 = 2`를 만족하고, 한 수열의 부호를 뒤집어도 쌍이 유지되므로
`sum(A) = sum(B) = 1`로 정규화한다. multiplier 군 `(Z/333)^*`는 위수가
216이고 `C6 x C36`과 동형이며 부분군이 80개 있다. 부분군 `H`에 대해 `C(H)`는
모든 `h ∈ H`와 모든 `x`에 대해 `A(hx) = A(x)`, `B(hx) = B(x)`인 정규화된
Legendre pair 전체의 집합이다.

**주장.** 80개 부분군 중 72개에 대해 `C(H)`는 공집합이다. 나머지 8개
부분군 `<10,112>`, `<184>`, `<121>`, `<211>`, `<10>`, `<112>`, `<73>`과 자명군에
대해서는 열려 있다. 자명군의 경우는 제약 없는 원래 문제와 같다.

다른 두 대칭 유형은 이 부류들로 환원된다.

- `A`가 `H1`-불변이고 `B`가 `H2`-불변이면 그 쌍은 `C(H1 ∩ H2)`에 속한다.
- `A`가 `H`-불변이고 어떤 multiplier `μ`에 대해 `B = A∘μ`이면, 군이 가환이므로
  `B`도 `H`-불변이다. 따라서 그 쌍은 `C(H)`에 속한다.

### 배제 기준

아래 기준은 모두 쌍 방정식의 정확한 귀결이다. 부동소수점 파워 스펙트럼(PSD)은
계산된 `PSD(k)`가 `668 + 1e-6`을 넘는 후보를 버리는 데에만 쓴다. 누적
반올림 오차는 `1e-9` 미만이다. 쌍 조건은 모두 정확한 정수 PAF 값으로
확인한다.

- **mod 3** (2026년 보고서의 Theorem 1). `h = 2 (mod 3)`이면 `A`의
  3-compression `(u, v, w)`(`x = 0, 1, 2 mod 3`에 대한 합)는 `v = w`를
  만족한다. 그러면 `PSD_A(111) = (u - v)^2`이고 `B`도 마찬가지이다. 그런데
  `PSD_A(111) + PSD_B(111) = 668 = 4 * 167`은 두 제곱수의 합이 아니다. 이
  기준은 `K3 = ker((Z/333)^* -> (Z/3)^*)` 밖의 모든 부분군을 배제한다. `K3`의
  위수는 108(`C3 x C36`)이고 부분군이 30개 있다. 보고서 6.2절은 이 핵을 위수
  72인 `C2 x C36`이라고 적고 있다.
- **mod 37** (Theorem 1 다음에 있는 보고서의 주석). `H`가 `(Z/37)^*` 위로
  전사되면 37-compression은 `(c0, x, ..., x)` 꼴이고, `37 ∤ k`에 대해
  `PSD_A(9k) = (c0 - x)^2`이다. 같은 모순이 생긴다.
- **sum.** 궤도 위의 어떤 부호 배정도 합 1을 만들지 못한다. 궤도 크기에 대한
  정확한 DP로 확인한다.
- **T111.** `PSD_A(111) = N(u, v, w) = u^2 + v^2 + w^2 - uv - vw - wu`이다.
  여기서 `u + v + w = 1`이고 각 성분은 부호 111개의 합이다. `N(u, v, w)`와
  `668 - N(u, v, w)`가 모두 이런 노름이어야 하므로 허용값은 16개(16, 64, ...,
  652)뿐이다. 합이 1인 궤도 부호 벡터 중 허용값에 도달하는 것은 없다.
  `subgroup_table.py`가 서로 독립인 두 가지 정확한 DP로 이를 센다.
- **A37.** `H9 = <4>`이면 9-compression `a`는 `{1,4,7}`과 `{2,5,8}` 위에서
  상수이고, `PSD_A(37) = N(a0, a3, a6)`도 허용값이어야 한다. `<31>`에서는 이
  개수가 0이다.
- **C37(m).** 37-compression `c`(`c_r`는 `x = r mod 37`인 `A(x)`의 합)는 위수가
  `m`인 `H37`의 잉여류 위에서 상수이다. 쌍은 0이 아닌 이동에서
  `PAF_c + PAF_d = -18`, 그리고 `sum c^2 + sum d^2 = 650`을 만족한다. 두
  프로그램이 이를 완전 열거한다. `comp_pairs.cpp`는 정확한 PAF 매칭을 쓰는
  meet-in-the-middle이고, `comp37_exact.py`는 단순한 정확 열거이다.
  `m = 4, 6, 9, 12, 18, 36`에 대해 두 프로그램 모두 허용 `c`가 각각 0, 2, 40,
  0, 2, 0개라고 보고하며 두 목록은 일치한다. 따라서 `m = 4, 12, 36`인 경우는
  공집합이다.
- **탐색** (`<28>`, `<46>`). 서로 다른 두 meet-in-the-middle 완전 탐색
  프로그램을 쓴다.
  - `lp_orbit_search.cpp`는 궤도를 두 쪽으로 나누고 정확한 3-compression을
    키로 쓴다. 조사한 벡터 수는 정확한 DP 개수와 같다.
  - `lp_column_search.cpp`는 `x mod 37` 클래스로 나누고, 37-compression을 허용
    `c`로 고정한 뒤 3-compression을 키로 쓴다.

  첫 번째 프로그램의 생존자 중 허용 `c`를 갖는 것들은 두 번째 프로그램의
  생존자와 정확히 같다(`crosscheck_survivors.py`). 어느 프로그램도 쌍을 찾지
  못한다.
- **C111** (`<85>`, `<175>`). 길이 111로의 3-compression
  `A'(y) = A(y) + A(y+111) + A(y+222)`를 쓴다.
  - 쌍 방정식: 0이 아닌 이동에서 `PAF_A' + PAF_B' = -6`이고
    `sum A'^2 + sum B'^2 = 662`이다.
  - `A'`에 대한 제약: `A'`는 `H mod 111`에 대해 불변이고, 그 37-compression은
    벡터가 2개인 C37(6)에 속한다. 제곱합은 551 이하이고, 3-compression은
    허용값을 가지며, `PSD_A'(k) = PSD_A(3k) <= 668`이다.
  - 이 두 군은 fibre `{37, 148, 259}`와 `{74, 185, 296}`를 추이적으로
    치환하므로 `A'(37)`, `A'(74)`는 `±3`이다.
  - 후보 4,000,000개 중 58,464개가 정확한 필터를, 4,296개가 PSD 필터를
    통과한다. 압축된 쌍은 존재하지 않는다.

  `lp_comp111.cpp`와 `lp_comp111_check.py`는 모든 중간 개수에서 일치한다.
  `lp_column_search.cpp`의 9-compression 모드로 돌린 전체 길이 탐색에서도 쌍이
  나오지 않는다. 각 탐색은 부호 벡터 56,833,665,984개를 조사하며, 키로는
  `comp9_pairs.py`가 두 방법으로 구한 허용 `<4>`-불변 9-compression 630개를
  쓴다.
- **lift 탐색** (`<64>`). 이 군은 `Z/9` 위에 자명하게 작용하므로 `A'(37)`,
  `A'(74)`에 제약이 없다. 후보 24,000,000개 중 허용 compression `A'` 648개가
  남는다(순서쌍으로 3,888개의 압축된 쌍, `data/adm111_h64.txt`). 이 compression을
  갖는 모든 `<64>`-불변 `A`, 즉 부호 벡터 45,112,963,608개를 두 프로그램으로
  열거했다.
  - `lp_lift111.cpp`: 조사 개수가 궤도별 선택 수의 곱과 같으며, PSD 생존자
    5,159,376개 중 쌍은 없다.
  - `a111` 모드의 `lp_column_search.cpp`: 같은 부호 벡터 45,112,963,608개를
    조사하며, PSD 생존자 5,159,376개는 첫 프로그램의 것과 똑같은 집합이고 쌍은
    없다.

**양성 대조군** (`controls.py`). 모든 탐색 프로그램은 brute-force로 센 쌍의
개수를 재현해야 하므로 어떤 대조군도 공허하게 통과할 수 없다.

- `lp_orbit_search`: 길이 9에서 순서쌍 972개, 길이 13에서 7,098개.
- 길이 63, `H = <2>`: 순서쌍 144개. `lp_orbit_search`, `u3`와 `a111` 모드의
  `lp_column_search`, `lp_lift111`이 모두 찾는다.
- 길이 63, `H = <11>`: 순서쌍 24개. 같은 프로그램들이 찾는다.
- `lp_comp111`은 길이 63의 모든 쌍의 3-compression을 허용값으로 보고한다.

### 주장하지 않는 것

- 668차 Hadamard 행렬의 존재에 대해서는 아무것도 주장하지 않는다. 미해결
  부류에 제약 없는 문제 `C({1})`이 포함되므로, multiplier 대칭이 없는 길이 333
  Legendre pair에 대해서도 마찬가지이다.
- 배제 결과는 짧은 증명인 mod 3과 mod 37을 제외하면 컴퓨터 계산 결과이다.
  계산에 의한 배제는 모두 서로 독립인 두 구현으로 다시 도출했고 양성 대조군도
  통과했다. 형식 검증이나 동료평가를 거친 것은 없다.
- 새로움을 주장하지 않는다. 2026년 보고서는 이 multiplier-궤도 경로를 6.2절에서
  simulated annealing과 함께 제안하지만 부분군별 결과는 보고하지 않는다. 그
  보고서 밖의 문헌은 확인하지 않았다.
- 부차 목표였던 길이 167의 Goethals–Seidel 4중쌍은 시도하지 않았다.
