# OOOOOOB 버전 C: 3의 배수 추측

이 추측은 Alon Danai, Paul Ellis, Thotsaporn "Aek" Thanatipanonda의 것으로,
*Generalizing OOOOOOB*([arXiv:2605.23213v1](https://arxiv.org/abs/2605.23213v1))의
버전 C에 관한 추측 3.1입니다. 우리가 아는 첫 공개 반례는 MathDB 사용자
`shivampatel`의 답글(2026-08-20)로,
[MathDB 게시물 374893](https://mathdb.com/p/374893/version-c-s-subtract-three-conjecture)에
달려 있으며 MathDB는 이를 미검증으로 표시합니다. 이 항목은 Lean으로 검사한
반박과 독립적인 계산 검증을 더합니다. 새로운 결과라고 주장하지 않습니다.

## 게임

OOOOOOB("one or one or one of both")는 고전적인 두 더미 게임입니다. 한 수에
한 더미에서 토큰 하나를 가져가거나 두 더미에서 토큰을 하나씩 가져가며,
마지막 수를 둔 사람이 이깁니다. 논문은 이 게임을 세 가지 방식으로 임의
개수의 더미로 일반화합니다. **버전 C**에서 한 수는 다음 중 하나입니다.

- 한 더미에서 토큰 하나를 가져갑니다.
- 비어 있지 않은 서로 다른 두 더미를 골라 각각에서 토큰을 하나씩
  가져갑니다.

두 더미의 크기는 같아도 됩니다. 둘 수 있는 수가 없는 사람이 집니다(정상
플레이). *P-위치*는 둘 차례인 사람이 최선을 다해도 지는 위치이고, 나머지
위치는 모두 *N-위치*입니다. 논문은 모든 더미의 토큰 수가 짝수인 위치가
P-위치임을 보입니다.

\(1\le i\le n\)에 대해 크기 \(i\)인 더미가 정확히 \(a_i\)개 있고 다른 더미는
없는 위치를 \((a_1,\dots,a_n)\)으로 씁니다.

## 추측

**추측 3.1**(v1 TeX 원본의 761–765행, 의역). 위치 \((a_1,\dots,a_n)\)이
모든 \(1\le i\le n\)에 대해 \(a_i\ge2\)를 만족하고, \(1,1,2,2,3,3,3\), 즉
\((a_1,a_2,a_3)=(2,2,3)\)이 아니라고 합시다. 그러면 이 위치가 P-위치일
필요충분조건은 토큰 수 \(\sum_i i\,a_i\)가 3으로 나누어떨어지는 것입니다.

논문은 모든 더미의 토큰이 3개 이하인 위치에 대한 보조정리로 이 추측을
설명합니다. 크기마다 더미가 충분히 많으면 버전 C는 한 수에 토큰을 1개나
2개 가져가는 빼기 게임처럼 움직이리라는 생각입니다. 저자들은 \(a_i\le5\),
\(n\le5\)에서 추측을 확인했다고 밝힙니다.

문자 그대로 읽으면 이 명제는 \(n=2\)도 포함하는데, 거기서는 논문의 보조정리
자체가 기록해 둔 단순한 이유로 성립하지 않습니다. 그래서 우리는 \(n\ge3\)으로
읽습니다([명제의 충실성](#명제의-충실성) 참고).

## 결과

**정리 (Lean).** 이 추측은 양방향 모두 거짓입니다.

| 위치 \((a_1,\dots,a_7)\) | 토큰 수 | 3으로 나눈 나머지 | 추측 | 실제 |
| --- | ---: | ---: | :---: | :---: |
| \(X=(2,2,2,2,2,2,3)\) | 63 | 0 | P | **N** |
| \(Y=(2,2,2,2,2,2,4)\) | 70 | 1 | N | **P** |

두 위치 모두 모든 가정을 만족합니다. \(X\)가 N-위치인 이유는 크기 1인 두
더미에서 토큰을 하나씩 가져가면 P-위치 \((0,2,2,2,2,2,3)\)이 되기
때문입니다. 이 위치에는 크기 1인 더미가 없으므로 추측은 이 위치에 대해
아무것도 말하지 않습니다.

이 둘은 MathDB 답글의 두 반례와 같습니다
([선행 연구와 상태](#선행-연구와-상태) 참고). 이 반박은 아직 사람이 검토하지
않았습니다.

## 증명 아이디어

Lean 파일은 게임 자체를 더미 크기의 멀티셋 위에서 정의하고, 커널이 검사하는
두 유한 인증서로 두 결과를 증명합니다.

1. **인증서.** \(S\)를 위치들의 유한 집합이라 합시다. 모든 \(y\in S\)와
   모든 수 \(y\to z\)에 대해, \(w\in S\)이거나 \(w\)의 모든 더미가 짝수
   크기인 응수 \(z\to w\)가 있다고 합시다. 그러면 \(S\)의 모든 위치는
   P-위치입니다. 토큰 수에 대한 귀납법으로, \(y\)에서 어떤 수를 두어도
   P-위치로 가는 응수가 있기 때문입니다. 이것이 `isP_of_cert`입니다.
2. **압축 표현.** 등장하는 모든 위치는 더미 크기가 7 이하이고 더미가 32개
   미만입니다. 이런 위치는 32진법 \(x-1\)번째 자리가 크기 \(x\)인 더미의
   개수인 수로 저장하고, 수는 코드 \(8x+y\)로 저장합니다. 인증서는 압축된
   위치들의 이진 탐색 트리이며, 각 노드는 합법적인 수마다 응수 코드 하나를
   저장합니다.
3. **다리.** `cnt_enc`, `Move.code`, `move_of_legal`은 한 위치의 수가 그
   압축 표현의 합법적인 수 코드와 정확히 일치함을 증명합니다. 그래서 커널이
   트리를 검사한 결과가 게임으로 옮겨집니다.
4. **두 인증서.** `CertX`는 위치 4,410개와 응수 72,523개로 이루어지며
   \((0,2,2,2,2,2,3)\)을 포함합니다. `CertY`는 위치 9,461개와 응수
   170,442개로 이루어지며 \(Y\)를 포함합니다. 각각 `decide +kernel`로
   검사하며, 정리 하나가 부분 트리 하나를 맡습니다.

정의, 다리 보조정리, 인증서 구성은 [DETAILS.ko.md](DETAILS.ko.md)에
있습니다.

## 명제의 충실성

이 추측에 대한 Formal Conjectures 명제가 없으므로 명제는 우리가 직접
정했습니다. 선택한 내용은 다음과 같으며, 모듈 docstring에도 적혀 있습니다.

- **위치.** 위치는 더미 크기의 멀티셋(`Multiset ℕ`)입니다. `position n a`는
  각 \(1\le i\le n\)에 대해 크기 `i`인 더미를 `a i`개 가지고 다른 더미는
  없으므로, \(n\)보다 큰 더미가 없습니다. \(1\le i\le n\) 밖의 `a` 값은
  무시합니다.
- **빈 더미.** 수에 의해 비워진 더미는 크기 0으로 멀티셋에 남고 어떤 수에도
  쓰이지 않습니다. `isP_zero_cons`는 이런 더미를 더하거나 빼도 결과가 바뀌지
  않음을 증명하므로, 결과는 빈 더미가 사라지는 게임의 결과와 같습니다.
- **수.** `Move s t`는 크기가 양수인 한 더미에서 토큰 하나를 가져가거나,
  크기가 양수인 서로 다른 두 더미에서 토큰을 하나씩 가져가는 수입니다. 두
  더미는 멀티셋의 서로 다른 두 원소이므로 크기가 같아도 됩니다.
- **결과.** `IsP s`는 `s`에서 어떤 수도 P-위치로 가지 않는다는 뜻입니다.
  모든 수가 줄이는 토큰 수에 대한 정초 재귀로 정의하므로, 둘 수 있는 수가
  없는 위치는 P-위치입니다(정상 플레이).
- **예외.** 정확히 한 위치 `exception = {1, 1, 2, 2, 3, 3, 3}`만
  제외합니다.
- **\(n\ge3\).** `statement`는 \(n\ge3\)을 가정합니다. 이는 명제를 약하게만
  하므로 `not_statement`는 문자 그대로의 읽기도 반박합니다. 문자 그대로
  읽으면 추측은 \(n\le2\)도 포함하며, \(n=2\)에서는 단순한 이유로 성립하지
  않습니다. \(1,1,2,2\)는 토큰이 6개이지만, 크기 1인 두 더미에서 토큰을
  하나씩 가져가면 짝수 더미만 남은 \(2,2\)가 됩니다(`two_counterexample`).
  같은 수로 모든 \((2,a_2)\)가 N-위치임을 알 수 있고, 더미 크기가 3 이하인
  경우에 대한 논문의 보조정리도 \((a_1,a_2)=(2,3k+2)\)를 예외로 적어
  둡니다. 따라서 저자들은 \(n\ge3\)을 뜻했을 것입니다. \(n\le1\)이면 주장은
  성립합니다. 빈 위치는 P-위치이고, 크기 1인 더미만 있으면 한 수는 더미를
  하나나 둘 없앱니다.
- **반례의 가정.** `X_counterexample`, `Y_counterexample` 두 정리는
  \(1\le i\le7\)에 대한 \(a_i\ge2\), 예외 위치와 다르다는 것, 그리고 토큰
  수를 정의로부터 증명합니다.

## 계산 교차 검증

증명은 Lean 인증서가 맡습니다. 코드를 공유하지 않는 두 풀이기가 Python
표준 라이브러리와 C++17 컴파일러만으로 결과를 다시 계산합니다.

- [`oooc_counts.cpp`](oooc_counts.cpp)는 크기마다 6비트로 압축한 더미
  개수를 다루고, 오픈 어드레싱 해시 테이블에 결과를 메모합니다.
- [`oooc_tuples.py`](oooc_tuples.py)는 더미 크기의 정렬된 튜플을 다루고,
  딕셔너리에 결과를 메모합니다.

두 풀이기 모두 \(X\)(N), \(Y\)(P), \((2,2,2,2,2,3,3)\)(토큰 69개, N),
\((2,2,2,2,2,3,4)\)(토큰 76개, P), \((0,2,2,2,2,2,3)\)(P)을 재현합니다.
\(n=7\)이고 모든 \(a_i\in[2,4]\)인 위치 2,187개에서 둘 다 같은 실패 15개를
찾습니다. \(n=6\)이고 모든 \(a_i\in[2,8]\)인 위치 117,649개에는 실패가
없습니다. C++ 풀이기는 \(n=3,4,5\)에서 모든 \(a_i\in[2,8]\)인 경우에도
실패를 찾지 못하므로, 모든 \(a_i\le8\)인 위치 가운데 실패가 있는 가장 작은
\(n\ge3\)은 \(n=7\)입니다.

[`gen_certificate.py`](gen_certificate.py)는 자체 메모 풀이기로 두 인증서
모듈을 다시 만들고, `--check`를 주면 커밋된 파일과 비교합니다.

**실패는 얼마나 견고한가?** 논문은 "sufficient piles of each size"(크기마다 충분한 더미)를 근거로
추측을 내놓습니다. 우리는 작은 상자 안에서 모든 \(a_i\ge t\)인 위치들의
실패를 세었습니다(컴퓨터 보조 결과이며 형식화하지 않았습니다. 표는
[DETAILS.ko.md](DETAILS.ko.md#실패의-견고성)에 있습니다). 문턱을 \(t=3\)으로
올리면 \(n=7\)과 \(n=8\)에서 확인한 상자에는 실패가 없지만, \(n=9\)(\(a_i\in[3,4]\)인 위치
512개 중 20개. 모든 \(i\)에 대해 \(a_i=3\)인 위치도 포함되며, 두 풀이기
모두 이를 찾습니다)와 \(n=10\)(1,024개 중 593개)에서 다시 실패가 나옵니다.
\(t\ge4\)로 확인한 상자에는 실패가 없지만, 이 상자들은 \(n=9\)까지와
\(n=10\)의 단일 위치 \(a_i=4\)에서 멈춥니다. 이 자료는 추측을 살려 주는
문턱을 보여 주지 않습니다.

  OpenConjecture는 버전 C 추측(conj 2622)을 시도 없이 올려 두고 있습니다.
  검색 내역은 [DETAILS.ko.md](DETAILS.ko.md#선행-연구)에 있습니다.

MathDB, OpenConjecture, 저자들을 비롯해 어디에도 아무것도 제출하지
않았습니다. 외부 제출에는 사람의 승인이 필요합니다.

## 재현

저장소 루트에서:

```bash
lake build AgenticConjectures.OooooobVersionC
python3 scripts/check_axioms.py
```

mathlib이 빌드되어 있으면 네 모듈은 Apple M5 Max에서 실제 시간으로 약 1분
걸립니다. `CertY`(44–48초)와 `CertX`(18–20초)가 병렬로 빌드되고, 이어서 주
모듈이 4–6초 걸립니다.

이 디렉터리에서:

```bash
g++ -O3 -std=c++17 oooc_counts.cpp -o /tmp/oooc_counts && /tmp/oooc_counts --ci
python3 oooc_tuples.py
python3 gen_certificate.py --check
/tmp/oooc_counts --version-b
python3 oooc_tuples.py --version-b
python3 oooc_tuples.py --full
/tmp/oooc_counts box 9 3 4
```

처음 다섯 명령이 CI 검사이며, 각각 약 1초, 22초, 8초, 1초, 1초 걸립니다.
`--version-b`를 주면 두 풀이기가 논문의 버전 B 위치 세 개를 다시
계산합니다. 이는 [DETAILS.ko.md](DETAILS.ko.md) 끝의 관련 메모를 위한
것입니다. `--full`은 Python 풀이기에 \(n=6\) 상자를 더합니다(약 2.5분).
`box n lo hi`는 모든 \(a_i\in[lo,hi]\)인 위치 중 실패를 모두 출력합니다.
견고성 상자들의 실행 시간은 [DETAILS.ko.md](DETAILS.ko.md#실패의-견고성)에
있습니다.
