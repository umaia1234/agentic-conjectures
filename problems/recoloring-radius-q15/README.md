# Graph-colouring reconfiguration radius, Question 15

This directory records an exact finite verification of Cambie–Cames van
Batenburg–Cranston Question 15. For \(k=3\), no counterexample exists among
the simple graphs on 1–7 vertices. This is a bounded
partial result; the general question remains open.

## Source and statement

For a graph \(G\), the vertices of its \(k\)-recolouring graph
\(\mathcal C_k(G)\) are the proper \(k\)-colourings of \(G\). Two colourings
are adjacent when they differ at exactly one vertex. The published question,
for \(k\ge3\) when both consecutive recolouring graphs are connected, asks:

> “Is it necessarily true that
> \(\operatorname{rad}\mathcal C_k(G)\ge
> \operatorname{rad}\mathcal C_{k+1}(G)\)?”

Primary source: Stijn Cambie, Wouter Cames van Batenburg, and Daniel W.
Cranston, “Sharp Bounds on Lengths of Linear Recolouring Sequences,”
*Electronic Journal of Combinatorics* 33(1) (2026), #P1.18,
[doi:10.37236/13788](https://doi.org/10.37236/13788), Question 15.

## Exact bounded result

The fixed graph6 dataset contains one representative of every unlabelled
simple graph on 1–7 vertices. Among them, exactly 145 graphs
have both \(\mathcal C_3(G)\) and \(\mathcal C_4(G)\) connected. Exact radius
computations find no graph with
\(\operatorname{rad}\mathcal C_3(G)<\operatorname{rad}\mathcal C_4(G)\).

| order \(n\) | atlas graphs | both recolouring graphs connected | counterexamples |
|---:|---:|---:|---:|
| 1 | 1 | 1 | 0 |
| 2 | 2 | 2 | 0 |
| 3 | 4 | 3 | 0 |
| 4 | 11 | 7 | 0 |
| 5 | 34 | 13 | 0 |
| 6 | 156 | 34 | 0 |
| 7 | 1,044 | 85 | 0 |
| **total** | **1,252** | **145** | **0** |

The result does not settle Question 15 for graphs of order at least eight or
for any comparison \(k\to k+1\) with \(k>3\). No novelty claim is made.

## Verification design

`atlas_1_7.g6` was generated by NetworkX 3.6.1 `graph_atlas_g()`, omitting
only the zero-vertex graph. It has 1,252 unique records and SHA-256
`ad68465d32eb7679a1ed8b0aa7a7f1da366da9b1ef8566b04664c504e8876255`.
The per-order counts above are checked before either radius computation.

Two implementations then audit the claim.

1. `recolor_radius_exact.cpp` decodes graph6, enumerates all labelled proper
   colourings, materialises each recolouring graph, and computes its exact
   radius by integer BFS. Global colour permutations preserve eccentricity,
   so one restricted-growth source per colour-permutation orbit suffices.
2. `verify_atlas.py` has a separate graph6 parser and tuple-state BFS. For a
   disconnected \(G\), it uses the exact identity
   \(\mathcal C_k(G_1\mathbin{\dot\cup}G_2)=
   \mathcal C_k(G_1)\mathbin{\square}\mathcal C_k(G_2)\), so connectedness is
   componentwise and radii add. It cross-checks this reduction against a
   direct, unreduced product BFS through order six: for \(\mathcal C_3(G)\)
   on every graph, and for \(\mathcal C_4(G)\) whenever
   \(\mathcal C_3(G)\) is connected.

The reductions used by both implementations are justified in
[DETAILS.md](DETAILS.md).

The trust boundary is the standard Graph Atlas enumeration and the ordinary
compiler/Python runtime. `generate_atlas_data.py` pins the NetworkX version,
order counts, uniqueness, and expected dataset hash; the CI verifier itself
has no NetworkX dependency.

## Reproduction

From the repository root, run:

```bash
g++ -O3 -std=c++17 \
  problems/recoloring-radius-q15/recolor_radius_exact.cpp \
  -o /tmp/recolor_radius_exact
python3 problems/recoloring-radius-q15/verify_atlas.py \
  --cpp /tmp/recolor_radius_exact
```

Expected output ends with:

```text
PASS dataset: 1252 unique records, SHA-256 ad68465d32eb7679a1ed8b0aa7a7f1da366da9b1ef8566b04664c504e8876255
PASS C++ exhaustive audit: 1252 graphs, 145 eligible pairs, 0 counterexamples
PASS independent Python audit: 1252 graphs through order 7, 145 eligible pairs, 0 counterexamples (...s)
```

On the recorded local run, the C++ audit took 1.12 seconds and the independent
Python audit took 53.53 seconds; the combined verification took 56.76 seconds
with a peak resident set size of about 22 MB.

To regenerate the fixed input independently:

```bash
python3 -m venv /tmp/recolor-atlas-venv
/tmp/recolor-atlas-venv/bin/pip install 'networkx==3.6.1'
/tmp/recolor-atlas-venv/bin/python \
  problems/recoloring-radius-q15/generate_atlas_data.py \
  /tmp/atlas_1_7.g6
cmp /tmp/atlas_1_7.g6 problems/recoloring-radius-q15/atlas_1_7.g6
```

## Faithfulness and conventions

The computation uses finite undirected simple graphs, labelled proper
colourings with the palette \(\{0,\ldots,k-1\}\), one-vertex recolouring moves,
ordinary graph distance, and minimum eccentricity as radius. These match the
published definitions; using zero-based rather than one-based colour names is
semantically irrelevant. Testing one unlabelled graph representative is
sound because recolouring-graph connectedness and radius are invariant under
graph isomorphism. The zero-vertex graph is outside the claimed search scope.

`recolor_radius_search.py` remains an exploratory NetworkX implementation.
The certificate command above uses only the fixed data, the C++ searcher, and
the independent standard-library Python verifier.
