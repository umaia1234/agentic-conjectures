# OEIS A297707 — 인증된 이전 소수 간격

## 상태

**부분 결과: 인증된 유한 범위이며, 상류의 250 경계를 인증한 것은 아니다.**
$2<n\le 175$인 모든 정수 $n$에 대해 간격

\[
g(n)=a(n)-\operatorname{prevprime}(a(n))
\]

이 $1$(오직 $n=3$에서)이거나 소수임을 증명했으므로, 이 범위에서 간격은 결코
합성수가 아니다. $176\le n\le 250$에서도 같은 계산이 $a(n)-g(n)$과 $a(n)$
사이의 모든 정수가 합성수임을 증명하지만, 끝점 $a(n)-g(n)$은 BPSW 추정 소수일
뿐이다. 따라서 그 구간에서는 실제 간격이 기록된 $g(n)$ 이상임이 증명되고 기록된
$g(n)$은 모두 소수이지만, **기록된 값이 실제 간격이라는 것은 증명되지 않았다**.
그러므로 상류 명제(경계 $250$)는 인증되지 않았다.

## 명제와 상류와의 대응

[OEIS A297707](https://oeis.org/A297707)은

\[
a(n)=\prod_{k=1}^{n-1} n!_k,\qquad
n!_k=\prod_{j=0}^{\lfloor (n-1)/k\rfloor}(n-jk)
\]

로 정의되며, $a(1),\dots,a(7)=1,2,18,768,90000,44789760,30494620800$이다.
FormalConjectures 스냅샷 [`297707_fd3973db.lean`](upstream/297707_fd3973db.lean)은
$a(n)-\operatorname{prevprime}(a(n))$이 합성수가 되는 가장 작은 $n>2$를 묻고,
`by sorry` 추측으로 다음을 진술한다.

```lean
theorem oeis_297707_conjecture_0 :
  ∀ n, 2 < n → IsComposite (a n - Nat.prevPrime (a n)) → 250 < n
```

여기서 `IsComposite m := 1 < m ∧ ¬ m.Prime`이고 `Nat.prevPrime m`은 `m`보다
엄격히 작은 가장 큰 소수이다. 상류의 `A297707`은 자연수 뺄셈 `n - j * k`를
쓰지만 $jk\le n-1$이므로 잘림이 일어나지 않고, 위의 곱과 일치한다.
$n\ge3$이면 $a(n)\ge 18$이므로 `Nat.prevPrime (a n)`은 실제 이전 소수이고
`a n - Nat.prevPrime (a n)`은 정확히 $g(n)\ge1$이다. 따라서 인증된 범위는
`oeis_297707_conjecture_0`의 사례 $2<n\le 175$을 Lean 밖에서 계산으로
해결한다(이 사례들에서는 가정이 거짓이다). $n>175$에 대해서는 아무것도 말하지
않는다. Lean 명제는 추가하지 않았다. 이 사례들을 Lean 안에서 이 데이터로
환원하려면, 형식적으로 검증된 ECPP 인증서 검사기를 커널이 최대 2028자리 수에
대해 실행해야 하고 약 42,700개의 합성수 증거도 커널에서 검사해야 하는데, 이
작업은 그것을 시도하지 않는다(그리고 이 저장소에서는 `native_decide`를 쓸 수
없다).

## 구조적 관찰

$n$ 이하의 모든 소수 $p$는 $n!=n!_1\mid a(n)$을 나누고, $a(n)$은 $[1,n]$의
정수들의 곱이므로 $a(n)$의 모든 소인수는 $n$ 이하이다. 따라서 $n$ 이하의 소수
$p$가 $1\le h<a(n)-n$인 $h$를 나누면 $p$는 $a(n)-h>p$를 나누고 $a(n)-h$는
합성수이다. 나머지 $h$(즉 $h=1$이거나 $h$의 모든 소인수가 $n$보다 큰 경우)를
*허용* $h$라 하자. $a(n)-g(n)$은 $n$보다 큰 소수이므로 $g(n)$은 허용 값이고,
따라서 합성수인 $g(n)$은 $n$보다 큰 가장 작은 소수 $q$에 대해 $q^2$ 이상이어야
한다. 계산 범위에서 $g(n)\ge q^2$인 경우는
$n=17,52,61,108$뿐이며(간격은 각각 소수 $433,3209,4691,13001$), 가장 큰 간격은
$g(241)=24359<251^2$이다. 이것은 합성수 간격이 드문 이유를 설명할 뿐 증명은
아니며, 아래의 증명은 계산에 의한 것이다.

## 방법

[`certify_a297707.py`](certify_a297707.py)(gmpy2 + PARI/GP)는 각 $n$에 대해
다음을 수행한다.

1. $a(n)$을 정확히 계산한다.
2. $h=1,2,\dots$를 차례로 본다. 허용되지 않는 $h$는 위 관찰에 의해 합성수이다.
   허용 $h$마다 $a(n)-h$가 합성수라는 증거를 저장한다. 증거는 $a(n)-h$를
   나누는 체(sieve) 소수 $q\in(n,10^7]$이거나, $N=a(n)-h$에 대한 Fermat 판정의
   실패 $2^{N-1}\not\equiv1\pmod N$이다. $a(n)-h$가 GMP의 BPSW 판정을 처음
   통과하는 허용 $h$가 $g(n)$이다.
3. $a(n)-g(n)$이 소수임을 PARI/GP 2.19.0 ECPP 인증서(`primecert`, 단일
   스레드, 큰 입력은 재개 가능한 부분 인증서로 분할)로 증명하고 즉시
   `primecertisvalid`로 검사한다.
4. $g(n)$이 $1$이거나 소수임을(시행 나눗셈으로) 기록한다.

$a(n)-1$의 $N+1=a(n)$이 완전히 소인수분해되어 있어 $N+1$(Lucas) 증명이 더
저렴했을 $g(n)=1$인 경우는 $n=3$에서만 나타나므로, 전 구간에서 ECPP를 썼다.
체로 결정되지 않은 모든 허용 $h$에서 Fermat 증거를 찾았다(밑 2 이외의 밑은
한 번도 필요하지 않았다).

[`verify_a297707.py`](verify_a297707.py)는 Python 표준 라이브러리만 필요한
독립 검사기이다(가능하면 속도를 위해 gmpy2를 쓴다). 각 레코드에 대해 자체
곱셈 루틴으로 $a(n)$을 다시 계산해 SHA-256 다이제스트를 비교하고, 간격의 모든
정수를 다시 검사하며(허용되지 않는 $h$는 작은 소인수로, 허용 $h$는 저장된
인수 또는 Fermat 증거로 검사하고, 증거 목록이 $g(n)$ 미만의 허용 $h$를 정확히
덮는지 요구한다), 끝점이 $3.3\cdot10^{24}$ 미만이면 결정적 Miller–Rabin으로,
인증서가 주어지면 **PARI ECPP 인증서를 자체 아핀 타원곡선 연산으로 검사**하여
소수임을 증명한다(각 단계마다 $\gcd(N_i,6)=1$, 비특이 곡선,
$q_i>(N_i^{1/4}+1)^2$, $[s_i]P_i\ne O$, 모든 모듈러 역원이 유효한 상태에서
$[q_i][s_i]P_i=O$, 그리고 마지막 $q<2^{64}$는 Miller–Rabin으로 증명). 선택적으로
PARI의 `primecertisvalid`(`--pari gp`)로도 검사하고, $g(n)$이 $1$이거나
소수인지 확인한다.

## 데이터와 인증서

- [`a297707_gaps.jsonl`](a297707_gaps.jsonl): $3\le n\le250$마다 한 줄이며,
  `g`, 자릿수, $a(n)$과 끝점의 SHA-256 다이제스트, 증거(`factor`: `[h, q]`
  쌍, `fermat2`: 밑 2 Fermat 증거가 있는 $h$, `fermat_other`: 비어 있음),
  `endpoint`를 담는다. $n\le 175$에서 `endpoint.method`는 `ecpp-pari`이며
  인증서의 SHA-256, 크기, 단계 수, PARI 벽시계 시간(단일 스레드, 다른 작업과
  공유되어 부하가 큰 기계에서 측정. 첫 시도가 중단되어 저장된 부분 인증서에서
  재개한 $n=53,54,120$은 마지막 시도만 측정)을 기록한다. 그보다 큰 $n$에서는
  `bpsw-only`이다.
- [`certs/`](certs/): $3\le n\le50$의 ECPP 인증서 `n<n>.gp`(PARI 출력 형식,
  총 441 KB). CI에서 다시 검사된다.
- $51\le n\le 175$의 인증서는 **로컬 전용**이다(총 46 MB, 가장 큰 것은
  $n=173$의 882 KB). SHA-256 다이제스트는 데이터 파일에 있다. PARI/GP 2.19.0과
  단일 스레드에서 생성기는 결정적이다. $n=40,53,54,120,150$의 인증서를 다시
  생성했더니 기록된 SHA-256 다이제스트가 정확히 재현되었다. 다른 방식(예: 다른
  PARI 버전)으로 얻은 인증서는 바이트 단위로 다를 수 있지만, 유효하면 검사기는
  그것이 기록된 인증서가 아니라는 사실을 보고하면서 받아들인다.

데이터 요약: $g(3)=1$이고, $4\le n\le250$의 모든 $n$에서 기록된 $g(n)$은
소수이다($n\le175$에서는 그것이 실제 간격임이 증명됨). 인증된 가장 큰 간격은
$g(147)=17827$이고, 기록된 가장 큰 간격은 $g(241)=24359$이다. 인증된 범위에는
인수 증거 29,960개와 밑 2 Fermat 증거 12,712개가 쓰였다(모든 $n\le250$에서는
각각 65,857개와 30,952개). $n=175$의 끝점은 2028자리이고 그 인증서는 ECPP
213단계이다.

## 재현

필요 조건: `gmpy2`가 설치된 Python 3, PARI/GP 2.19.0(`gp`). 시간은 다른 작업과
공유된 Apple M5 Max(부하 평균이 자주 50을 넘음)에서 작업 프로세스 4개로
측정했다.

```bash
cd problems/oeis-a297707
OUT=/tmp/a297707_out
# 3 <= n <= 250의 간격과 합성수 증거: 벽시계 약 20분
for s in 3 4 5 6; do python3 certify_a297707.py search $s 250 --stride 4 --out $OUT & done; wait
# 3 <= n <= 175의 ECPP 인증서: 벽시계 약 3시간. n별 단일 스레드
# 실행 시간의 합은 10.6시간(n = 175 하나에 737초)
seq 3 175 | xargs -P 4 -I{} python3 certify_a297707.py prove {} {} --out $OUT
python3 certify_a297707.py merge --out $OUT   # $OUT/a297707_gaps.jsonl 생성
```

ECPP 시간은 자릿수의 대략 세제곱에 비례해 늘어난다($100\le n\le 175$에 맞춘
지수는 2.8). 같은 환경에서 $n=250$(3317자리)에 도달하려면 단일 스레드 ECPP
시간이 대략 50시간 더 필요하다.

검색 레코드에는 시간 필드도 들어 있으므로, 다시 생성한 데이터 파일은 커밋된
파일과 그 필드에서만 다르다.

## 검증

```bash
cd problems/oeis-a297707
# CI 부분집합: 3 <= n <= 50 전체, 순수 Python(로컬에서 26초)
python3 verify_a297707.py --certs certs --max-n 50 --require-certified-through 50
# 다시 생성한 인증서로 하는 전체 로컬 검사(gmpy2 사용 시 CPU 86분)
python3 verify_a297707.py --certs $OUT/certs --pari gp --require-certified-through 175
```

$n$ 구간 4개(`--min-n`/`--max-n`)로 나누어 실행한 전체 검사는 부하가 큰 기계에서
벽시계로 약 35분 걸렸다. 이 검사는 $176\le n\le250$의 합성수 증거도 다시
검사하고, 그 끝점들을 밑 2 강한 추정 소수 판정으로 다시 확인하며, 그 $n$들을
끝점이 증명되지 않은(BPSW만 통과한) 경우로 나열한다.

## 주장하지 않는 것

- $176\le n\le250$에서는 하한(실제 간격이 기록된 값 이상이라는 것)만 증명되며,
  $n>250$은 계산하지 않았다. $n=250$까지의 BPSW 선별은 상류의 "250보다 크다"는
  명제를 추정 소수 수준에서만 재현한다.
- 상류 정리는 Lean으로 형식화되거나 증명되지 않았다. 소수성 증명은 두
  프로그램(이 저장소의 Python 검사기와 PARI/GP)이 검사한 ECPP 인증서이며 Lean
  증명이 아니다.
- 무한 문제(합성수 간격이 언젠가 나타나는지)는 열려 있다. 구조적 관찰은 작은
  $n$에서 그런 일이 일어나기 어려운 이유를 설명할 뿐이다.
- 새로움을 주장하지 않는다. 경계 250은 OEIS 항목을 옮긴 상류 형식화에 이미 적힌
  값이다. 이 작업은 $2<n\le 175$에 대한 인증서와 $n=250$까지의 추정 소수 수준
  재계산을 더할 뿐이다.
